## Design and implementation boundaries

Coordinated raw application/pdf upload, shared DTOs, private original attachments, current verified-member authorization, immutable extraction versions, appended corrections and durable outbox before dependent implementation. Existing UUID organizations/memberships remain authoritative. Reads allow current members; owner/admin/analyst write; viewer does not. Native ERP/email/OCR/AI integrations and financial decisions are absent.

API routes validate organization/resource IDs and Origin for writes, throttle mutations in PostgreSQL and check upload authorization onRequest before buffering up to 10 MiB. Resource lookups include the tenant; queue payloads must match persisted outbox/run/document/actor identifiers. Workers check verified initiating membership before parsing and again before commit. Private keys are server-generated, omitted from DTOs, and not accepted from documents or queue inputs. Downloads recheck access after storage read, verify checksum/length, and use attachment, no-store, nosniff and sandbox headers.

The PDF parser receives actual bytes in an empty-environment/empty-execArgv worker, fixed installed module location and no expected answers. Evaluation, unnecessary font/network behavior and XFA are disabled. A 10-second termination deadline, managed-heap limits, 50 pages and 200,000 total text characters bound processing. It is not an OS sandbox or full native-memory limit. Output is escaped text with one-based page/snippet evidence; missing/ambiguous fields remain explicit. Textless input requires unsupported OCR. Extraction ends needs_review, not accounting approval.

## Findings addressed in the reviewed source

- **DOC-ARCH-01 — high, source-resolved:** a stale worker's transient failure could reset document status after losing the run fence. Run/document claim is now transactional; transient and terminal updates require the current UUID token, processing state and unexpired lease. Document updates occur only after a successful owned-run transition. The lease is 45 seconds, longer than the nominal 10-second storage plus 10-second parser deadlines.
- **DOC-ARCH-02 — high, source-resolved:** BullMQ retry limits alone could be reset indefinitely by durable re-publication. PostgreSQL now counts attempts across delivery/recovery, stops transient processing after three attempts, records PROCESSING_RETRIES_EXHAUSTED and completes outbox intent. Redis remains transport; reconciliation covers work lost after publication and never treats a queue job ID as sufficient business idempotency.
- **DOC-ARCH-03 — medium, source-resolved:** timestamp/random-UUID correction ordering and a count/read cap could lose the actual latest concurrent correction. The document atomically reserves a monotonic revision bounded at 1000; unique document/revision and revision-ordered reads preserve deterministic latest values. Terminal extraction content and original evidence are retained.
- **DOC-ARCH-04 — medium, source-resolved:** currentRunId had no enforced tenant/document relationship. The schema/migration now enforce the composite organization/document/run link, as do correction/outbox provenance relations.
- **DOC-SEC-01 — medium, source-resolved:** upload authorization/throttling originally happened after the body parser. The upload onRequest guard now runs before buffering; the guarded request actor is reused only for that request. Verified-user checks are explicit in use-case/worker membership authorization. The final authorization recheck distinguishes denied membership from transient database failure.
- **DOC-ARCH-05 — high, source-resolved:** compensation on an ambiguous commit failure could delete a successfully committed original. The catch path now checks the generated candidate ID on the primary before deleting its key. A matching committed document is reloaded; an unavailable or inconsistent check preserves the private object and returns UPLOAD_COMMIT_UNCERTAIN. Only confirmed-absent candidates are compensated. Possible inaccessible orphans are preferred to deleting a potentially committed original; there is no distributed transaction claim.

No unresolved critical/high source finding remains in this reviewed scope. Runtime closure of these fixes still requires the CI evidence below; source inspection alone does not establish their recovery behavior.

## Frontend and accepted limitations

Reviewed user/organization/document-scoped query keys and response attribution, fresh context gating, permission-conditioned mutations, current-run correction references, revision-ordered correction selection and the separation between original extraction/evidence and corrections. Upload navigation and download DOM effects have mounted guards. Downloads use a temporary Blob attachment, not an active inline PDF viewer. No original storage URL, arbitrary HTML or financial-approval action is exposed.

ADR 0004 explicitly accepts the initial application's direct Prisma/concrete extraction dependency as a bounded implementation tradeoff; the pure financial domain remains independent, and a fully adapter-independent application layer is not claimed. There is no automatic orphan collector, universal PDF/table recognition, OCR, actual CargoWise integration or real-customer accuracy validation. Previously documented MFA, trusted-proxy, retention, backup/restore and deployment controls remain rollout gates. These limitations do not waive tenant, provenance, idempotency or recovery checks.

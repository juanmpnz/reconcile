## Follow-up findings and corrections

- **SEC-01 — high verification gap, source correction reviewed:** coordinator-reported CI run https://github.com/juanmpnz/reconcile/actions/runs/38619915838 accepted a hostile-Origin organization POST in the test environment. Installed `better-auth/dist/context/create-context.mjs` defaults `skipOriginCheck` to true under `isTest()` when `advanced.disableOriginCheck` is unspecified; its middleware also skips legacy CSRF checks under that setting. This explains the failed test and is not evidence of a confirmed production bypass. The initial source review missed this environment default. `packages/auth/src/index.ts` now explicitly sets `disableOriginCheck: false` and `disableCSRFCheck: false`. `apps/api/src/application.ts` independently requires exact allowed Origin for auth POST, rejects missing/null/untrusted Origin and cross-site Fetch Metadata, and permits legitimate no-Origin email GET links. The current patch was inspected independently. Full native-auth regression must pass in corrected CI before runtime closure.
- **SEC-02 — medium HTTP contract mismatch, source correction reviewed:** installed Better Auth rate limiting returns `X-Retry-After`, while the initial integration assertion expected standard `Retry-After`. The 429 response existed; limiter absence was not demonstrated. The bridge now preserves native response headers and maps a numeric native delay to standard `Retry-After` when absent. QA's updated test asserts preservation and equality. Full limiter acceptance remains a real-DB CI responsibility.

Reviewed the final correction in `apps/api/src/application.ts`, explicit native security flags in `packages/auth/src/index.ts`, and updated integration source. Ran `pnpm --filter @reconcile/api build` successfully. An initial bridge probe without service environment exited during app initialization; rerunning with `.env.example` succeeded. The independent bridge-only Fastify probe used a stub auth handler and verified four forbidden writes never reached that handler, a trusted write did, numeric retry normalization was preserved, and no-Origin email GET remained routable. This probe does not mock or certify the product's actual authentication/database flow; it verifies only adapter behavior. No PostgreSQL acceptance or corrected CI success is claimed here.

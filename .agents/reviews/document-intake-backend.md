Scope: shared document contracts, PostgreSQL document/run/correction/outbox schema and migration, API routes/private storage adapter, isolated PDF.js text parser, durable document worker/dispatcher. Read AGENTS.md, expert workflow, backend/data/document-AI profiles, implementation phase 2, document product/design brief and ADR 0004 before completing dependent changes. Official PDF.js API reference consulted at https://mozilla.github.io/pdf.js/api/draft/api.js.html and https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html; current registry PDF.js distribution pinned to 6.4.299. Uses actual uploaded PDF bytes and no expected-result imports.

Implemented verified current-member permissions on every use case, exact Origin protection and shared PostgreSQL mutation throttling, authorized private attachment downloads, checksums and tenant-local deduplication. Upload authorization runs onRequest before buffering. Store keys are server-owned and never in transport DTOs. New object compensation only removes the losing upload's key; process crashes between S3 write and DB commit may leave inaccessible orphan objects requiring operational cleanup.

Parsing: fixed installed module, bytes only, explicit empty environment/execArgv, no document evaluation or remote source URL, suppressed parser output, terminable thread with 10-second deadline, 128 MiB managed heap, 50 pages and 200,000 text characters. Six label-derived candidates retain page/snippet, null/missing/ambiguous states. Real extraction ends needs_review; textless PDF explicitly OCR_UNSUPPORTED. This is not OCR, universal field extraction, malware scanning or an OS sandbox.

PostgreSQL document/run/outbox intents commit together. Worker reloads persisted identifiers and verified initiating member, claims run/document state transactionally, fences commits with a UUID token and 45-second lease. Persisted attempt budget ends transient failures after three attempts; queue delivery and lost-Redis re-publication are idempotent. Corrections reserve a bounded monotonic revision and append original-preserving changes. Composite tenant/document/run constraints include currentRun and prevent cross-tenant provenance.

Sequential checks passed: Prisma schema/migration diff generation, Prisma client generation, direct TypeScript builds for database/contracts/document-processing/application, and direct ESLint on owned source. Root separately checked API/worker types after installing workspace manifests. Actual extraction of all four synthetic PDFs passed with expected page evidence and operational total missing; no fixture answers are supplied to the parser. No real-service acceptance is claimed by this record: PostgreSQL/S3/BullMQ recovery/isolation tests remain the independent QA gate and CI evidence must identify its commit.

Independent review findings addressed during implementation: stale failure fencing; atomic run/document claim; persisted retry budget; lease longer than bounded storage+parse operations; correction revision/cap race; currentRun composite FK; upload auth before buffering; no inherited secrets/launch flags in parser; transient DB failure not classified as access revocation. Final recheck required after any subsequent code correction.

Post-snapshot compensation correction: a rejected PostgreSQL transaction can mean a lost commit acknowledgement. Upload error handling now queries the generated candidate document ID on the primary before removing any object. Matching committed metadata is returned without deleting its original; an unavailable ownership lookup or inconsistent candidate preserves the private object and reports a bounded uncertain-commit error. Only a confirmed absent candidate permits compensation of that candidate's key. Independent QA was requested to exercise a real commit followed by a synthetic transport-acknowledgement failure. This does not make S3 and PostgreSQL a distributed transaction.

Real-service CI follow-up: run 38706903198 exposed a genuine module-runner incompatibility. The production parser used import.meta.resolve, which Vitest/Vite transforms without a resolve function; errors occurred before the isolated parser started and were classified as transient. A direct production-adapter Vitest test reproduced the exact TypeError on both actual fixture and malformed bytes. Resolution now uses Node createRequire(import.meta.url).resolve plus pathToFileURL to locate the same fixed installed PDF.js module in Node and Vitest. Two actual-adapter regression cases now pass without stubbing parsing. Source text retains real newline characters. Upload also rejects unsupported MIME in its authorized onRequest stage before Fastify tries to parse a mismatched body. Independent real-service CI rerun remains required.

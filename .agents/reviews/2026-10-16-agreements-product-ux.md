## Product and domain assessment

The implementation addresses one-time source upload/reuse and explicit per-invoice annual/spot selection without automatic provider-based assignment. Each immutable record has its own UUID; a new record is an explicit replacement, not a grouped contract-version editing workflow. A spot record is operation-scoped. Selection preserves other invoice bindings, includes contextual service date/route/distance and requires a reason/current fingerprint. Creating a record does not silently select it. Selection changes advance operation revision; immutable terms and selected source provenance enter the input fingerprint/snapshot.

Fixed-trip, per-kilometer and finite `[fromKm,toKm)` bands have distinct typed representations. Exact Decimal calculation applies a band rate to the whole distance; no hidden rounding, FX, tax merge or tolerance is introduced. Strict invoice quantity/unit, currency, provider, scope, date and evidence checks produce not-verifiable when unsupported. Price match explicitly does not establish service performance. Source snippets are checked against actual persisted extraction pages; manual condition review is identified, without pretending arbitrary tables were extracted.

Bounded limitation: one service and one route/scope per immutable record, without arbitrary commercial-contract clauses/exclusions. Selecting this record does not borrow legacy exclusion conditions for other services on the same invoice. The unbound legacy demo path remains available. Another limitation is intentional source-wide suppression: once any invoice selects a published record, its source PDF is omitted from mutable analysis facts for that operation. Other invoices previously relying on that source need explicit selections. Application warning and user guide describe this transition. These are documented capacity/representation limits rather than claims of complete contract understanding.

## UX and visual assessment

Organization navigation exposes “Tarifas y acuerdos”. The table presents provider/scope, reusable/spot, validity, immutable ID, pricing and evidence. Creation reuses existing tariff/quotation PDFs or the established upload flow, with visible extraction requirements, original/evidence access, required labeled review fields and acceptance confirmation. Per-invoice operation cards expose the selected basis/version/context and three actions: select saved, create reusable and create spot. Creation clearly asks for subsequent explicit selection. Dialogs preserve drafts after service errors and require conscious conflict reconciliation. Writer/viewer and active-analysis states use existing capabilities. Layout uses existing compact primitives with wrapping action groups, semantic fieldsets and bounded original text.
